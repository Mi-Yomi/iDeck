## Defects fixed

1. **Root loader environment:** device loader checks used root with a Steam-owned `LD_LIBRARY_PATH`. They now invoke the system `setpriv` with a clean environment, drop to UID/GID1000, and only then set the vendor path for `/usr/bin/ldd`. The existing namespace helper, its two user preflights and CEF sandbox arguments remain byte-for-byte unchanged.
2. **Real return-to-Desktop completion:** the old device action only acknowledged a shutdown request. It now waits at most 20 seconds for UID1000 Steam/private mount-namespace holders to disappear and for the launch supervisor's lock to become available. Only then does it emit `IDECK_STEAM_DESKTOP_READY`. Writers/launcher timeout is a blocker. No signals, forced termination or user-file cleanup are introduced. Original desktop processes are excluded; an unrelated UID1000 private namespace conservatively prevents the completion claim. Browser-library checks apply to launch; a missing optional browser library does not prevent sending shutdown.
3. **Interrupted dpkg:** existing packages can acquire pending/awaited triggers while new dependencies are installed. Resume now permits those two states only in the `dependencies` phase with exactly unchanged baseline versions. Unpacked baseline packages, unknown packages and version drift still fail closed. The installation cannot advance to `client` without the original strict empty audit and final version checks.
4. **Cache traversal:** a fresh root-only cache parent could prevent the ordinary user's ZIP installer from reading verified parts. The root-owned cache parent is explicitly 0755, with read-only client ZIPs. Root installer state remains separate. Synthetic real-IO retry checks assert this permission.
5. **Publication trust/durability:** a mutable publication receipt is read through `O_NOFOLLOW`/nonblocking descriptor checks, requires a single regular UID1000-owned file, and is bounded to 64 KiB. Unknown journal phases or malformed baselines fail before resumption. The client receipt/beta files are fsynced before atomic no-replace directory publication. Native ELF inspection reads only the 20-byte header.
6. **Delivery without another secret:** ready-fetch can take a non-secret, exact same-repository asset API `payload_url` from the reviewed lock. It reuses `IDECK_DEBIAN_PAYLOAD_TOKEN` only for that exact API scope, matching the existing GUI mechanism. An explicit Steam token/URL remains optional. The fallback is never read for another repository/path, signed arbitrary URL or query, and Authorization is stripped on redirects. The blocked lock still stages only its exact marker and needs no token or URL.
7. **New asset provenance/notices:** source bindings now include the exact GUI package lock, kernel source lock and original notice source. The bootstrap records each added network module's compiled licence declaration alongside its digest, version magic and modloop origin. The new notice retains the Debian/package notices and the original shared Alpine terminal notice, including its unresolved exact BusyBox source/configuration limitation; it corrects the inherited GUI notice’s bundle-location reference. It identifies exact Alpine kernel source/config locations and original iDeck script/probe sources, without claiming a complete redistribution review. No additional third-party package, Valve binary or account data is added to the seed.

## Storage, Stop and input review

The prepared raw image is logically 12 GiB but its offline host copy is sparse (about 1.3 GiB physically allocated). Neither the builder nor app treats that saving as free capacity: the builder requires 16 GiB free before a new copy; the app requires 12 GiB + 1 GiB reserve and streams the full expanded seed to its unpublished file. Existing real disk-owner tests cover interrupted import, symlink/hardlink/competing owner, low space and no-replace publication. Steam adds a bounded gzip decoder and separate compressed/raw digests; it never attaches the bundle seed to QEMU or resizes an existing app disk. The narrow 12-GiB exception is UUID-scoped; ordinary ext4 profiles retain their 4-GiB cap.

Actual read-only debugfs inspection of the prior candidate found no `/home/ideck/.steam` or `/home/ideck/.local/share/Steam`; the new candidate again derives exclusively from the hash-checked accepted GUI seed. The raw is never mounted on this host. Fresh strict fsck and raw/gzip checks are retained as asset-integrity evidence, not a guest-boot or privacy scan of every possible arbitrary file. No local Steam/account disk was used.

Accepted GUI, Terminal, Debian and native recipe locks are unchanged from db5. The original guest shutdown function, lifecycle fail latch, retained QEMU owner/thread and one-runtime-per-process guards remain in use. `IDECK_STOP_V1` is handled by the independent supervisor while installer/action children run in the background; those children close FD3. Stop kills guest writers before sync/unmount; failed unmount or host fsync cannot be reported clean. Runtime Stop/return-to-Desktop behavior still needs a physical-device test.

The actual persistent bootstrap shell's feature-advertisement and LSE-probe failure branches were executed with controlled command results: a missing feature or failed probe emitted the precise blocker and did not emit LSE PASS. This verifies failure propagation, **not execution of LSE on the new iOS QEMU**. Recovery/Stop is established before that gate. The Steam argv requires network consent; accepted A72/`-nic none` profiles remain unchanged.
