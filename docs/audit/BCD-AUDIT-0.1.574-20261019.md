## 2. Находки

Уровни: **[В]** высокий, **[С]** средний, **[Н]** низкий.

### 2.1 Поставка и процесс

- **[В] Форк нельзя собрать и доставить на устройство.** Активного CI нет,
  `libntdll_unix.a` и прочие Wine unix-библиотеки в репо не лежат, значит
  нужна полная нативная сборка (LLVM 15, Wine, FEX, генераторы) на macOS.
  Владелец сейчас запускает апстримную IPA 574, поэтому наш VA-фикс
  (`virtual_ios.c:22524`, `get_host_addr_space_limit`) на устройство не попадает.
  Нужно решить, как собирать: свой Mac + Xcode или ручной macOS-workflow без
  подписи и выгрузки, с отдельным бюджетом.
- **[С] Нет процедуры синхронизации с апстримом.** Этот merge сделан вручную.
  Апстрим выпускает версии почти ежедневно (573 → 574 за один день).
  Стоит записать процедуру: fetch → merge → проверить, что
  `.github/workflows` не появился, а `.disabled` совпадает с апстримом → короткая
  запись в `docs/`.
- **[С] Расхождения в документации миграции.** `docs/migration/AUDIT-20261019.md`
  указывает адрес приёма логов `madeira-log-intake...`, а в 574 он уже
  `bcd.bcd-logs.workers.dev` (`LogUpload.swift:27`, `FeedbackUpload.swift:22`).
  В `THIRD-PARTY-NOTICES.md:23` Wine указан как GPL-3.0-or-later, а
  `LICENSE-MADEIRA.md` закреплённого Wine говорит LGPL-2.1-or-later.

### 2.2 Приватность и внешние адреса

Все внешние адреса приложения (инвентаризация по `app/`):

| Назначение | Адрес | Когда |
| --- | --- | --- |
| Логи / фидбек | `bcd.bcd-logs.workers.dev/v1/{logs,feedback}` (сервер автора апстрима) | по нажатию |
| Проверка обновлений | `api.github.com/repos/thebcd69/bcd-games/releases/latest` (`BCDUpdates.swift:82`) | при старте, если включено |
| Рекомендации | `raw.githubusercontent.com/thebcd69/bcd-games/main/recommended/…` (`GameRecommendationsSource.swift:91-92`) | в фоне раз в 6 ч |
| Steam, GOG, steamstatic, Microsoft VC++, WineHQ Mono, StikDebug | официальные адреса | по действию |

- **[В] Логи и фидбек нашей сборки уйдут автору апстрима.** На устройстве
  владельца лог 19.10 уже отправлен туда через «Send Log» (это апстримная IPA,
  так и задумано). Для своей сборки нужен свой приёмник (например Cloudflare
  Worker) или только локальный экспорт; не перенаправлять на угаданный адрес.
- **[С] Проверка обновлений предложит апстримную IPA.** Для своей сборки
  она будет звать «обновиться» на чужой релиз и затрёт форк. Нужно указать
  на свои релизы или выключить.
- **[С] Рекомендации подписаны ключом апстрима.** Свои правила (например для
  Unity IL2CPP) нельзя раздать удалённо без своего ключа и адреса. Встроенный
  список при этом работает.
- **[С] Wine-префикс лежит в `Documents/wine`, а `UIFileSharingEnabled`
  включён** (`Info.plist:65`, `MadeiraDock.swift:65`). Всё содержимое `drive_c`
  (включая локальные данные Valve-клиента внутри Dock) видно в «Файлах» и через
  Finder по USB. Надо проверить, что Valve-клиент хранит в префиксе, и при
  необходимости вынести чувствительное в Application Support / исключить.
- **[Н] В логах есть путь контейнера приложения с UUID**; при ручной отправке
  он вычищается, а при пересылке файла вручную нет.

### 2.3 Память, адресное пространство, JIT (по логам владельца)

- **[В] Без `extended-virtual-addressing` Unity-игры падают на старте.**
  Лог 573: карта 454 ГБ, FEX получает запасную арену 4 ГБ
  (`virtual_ios.c:29490`, лестница `plan[]`), гостю остаётся ~1.4 ГБ кусками;
  UnityPlayer резервирует 512 МБ (`0x1ffff000`), самая большая дыра 369 МБ →
  `c0000017` → запись по NULL. В запусках 574 (после GetMoreRam,
  increased-memory=1; extended-va всё ещё 0) карта стала 512 ГБ, и FEX получил
  16 ГБ по `0x7c00000000` — игра прошла дальше. Что именно из этого (entitlement,
  сборка 574 или запуск через LiveContainer) расширило карту, логи не разделяют.
- **[В] Бесконечный цикл исключений вместо понятной ошибки.** В логе 573
  после первого падения UnityPlayer ~4 минуты повторял необработанный AV
  (2368 повторов, каждый с новым резервом 511 МБ «на бумаге» — итого
  1.2 ТБ запрошенного VA), пока процесс не умер. В коде есть «storm gate»
  (`signal_arm64_ios.c:147`, `:4962`) для штормов фолтов, но этот цикл
  (вложенные гостевые исключения с одним и тем же RIP) он не остановил.
- **[С] Предупреждение на странице игры знает только про память.**
  `BCDGamePage.swift:806` пишет про отсутствие increased-memory-limit, а про
  extended-VA молчит, хотя оно влияет на крупные 64-битные игры сильнее.
- **[С] JIT-пул урезается при старте** (`ml1036 ... SHRINKING to 560/624MB`).
  Большие образы (IL2CPP `GameAssembly.dll`) могут не поместиться. Для этого уже
  есть правило auto-tune `x64-image-nocopy` по строке `[jit-pool] EXHAUSTED (image`.
- **[Открыто] «Failed to load il2cpp» в No, I'm not a Human (сборка 574).**
  Нужен лог именно того запуска (`Documents/logs/NoImNotAHuman.exe-…txt`);
  auto-tune не нашёл подходящего правила («matched ;»).

- **[Н] Огромные файлы.** `ContentView.swift` 2.7 тыс. строк,
  `BCDGamePage.swift` 2.7 тыс., `virtual_ios.c` 34 тыс. со слоями

- **[Н] Диагностика в нативном коде всегда включена.** ~590 `dprintf` в
