# iDeck-BCD: сборка неподписанной IPA в GitHub Actions — 20 октября 2026

Решение владельца: Mi-Yomi/iDeck-BCD — публичный репозиторий для сборки
(GitHub-hosted runners, включая macOS, для публичных репозиториев бесплатны);
Mi-Yomi/iDeck — приватное зеркало с той же историей в `main`.

## Как собрать

1. GitHub → Mi-Yomi/iDeck-BCD → Actions → **Build iDeck-BCD IPA (unsigned)** →
   Run workflow (ветка `main`).
2. Ждать: полная нативная сборка (Wine, FEX, DXMT, LLVM 15, GnuTLS, FFmpeg) с
   кешами Actions; предел задачи — 6 часов (`timeout-minutes: 360`, как у
   апстрима). Первая сборка идёт без кешей и самая долгая.
3. Готовые файлы — артефакт `unsigned-ipa-<N>` на странице запуска (14 дней):
   `Madeira-0.1.N-unsigned.ipa` и `Madeira2-0.1.N-unsigned.ipa`. Их
   подписывают SideStore / AltStore / LiveContainer на устройстве.
   `N` берётся из `docs/local-build/BUILD-NUMBER`.

Артефакт публичного репозитория может скачать любой, кто видит репозиторий
(нужен вход в GitHub). Это распространение изменённого приложения: см.
`AGENTS.md` (свой брендинг, условия Metal Shader Converter).

## Чем workflow отличается от апстримного

`.github/workflows/build-ipa.yml` получен из
`docs/upstream-workflows/build-ipa.yml.disabled` (байт в байт апстримный):

- запуск только вручную; выполняется только в Mi-Yomi/iDeck-BCD (в приватном
  зеркале и форках задача пропускается и минут не тратит);
- токен только на чтение (Metal Shader Converter с 2026-10-07 лежит в репо,
  черновики релизов апстрима не нужны);
- удалены шаг подписи и OTA-публикации (B2/R2-бакеты, почта, P12) и его
  проверка; секретов в файле нет;
- добавлена выгрузка неподписанных IPA артефактом Actions на 14 дней.

Все шаги сборки и все проверки остались как у апстрима.

## Проверки: что починено, что проверено здесь

Апстрим собирает в приватном `thebcd69/madeira-bcd`, где есть файлы, которые
`tools/export-public.py` не выпускает в публичное дерево. Эти проверки упали
бы и на CI; теперь они пропускают отсутствующую часть с явным SKIP, а проверки
кода приложения выполняются полностью:

- `check-log-upload.py`, `check-feedback.py` — без `bcd-logs/` (сервер приёма
  логов) и `tools/pull-logs.py`; для приложения сохранён последний контракт
  сервера (поля, лимиты, виды отзывов);
- `check-feedback.py` — исправлена скрытая ошибка: `code()` обрезал строку по
  `//` внутри литерала, и идентификаторы с «madeira» не проверялись; теперь
  идентификаторы (`madeira-bcd/2`, ключ UserDefaults) не считаются текстом для
  человека;
- `check-vcruntime-mfc.py` — без `tools/fetch-vcruntime.md`;
- `check-vis-trace.py` — 19 списков рекомендаций (добавлен `unity`);
- `check-autotune.py` — нативный код не должен упоминать auto-tune: комментарий
  в `virtual_ios.c` переписан.

Прогнано на Windows-хосте (Python 3.14, без cc/swiftc/xcrun) всё, что
вызывает workflow: 133 команды. Падения, оставшиеся после правок, объясняются
этим хостом: нет компилятора C/Swift и Xcode, `fcntl`/`os.uname` в Windows,
нет прав на symlink, нет `python3`, CRLF в рабочей копии, сабмодули выкачаны
частично и на глубину 1 (проверки, которые дотягивают предковые коммиты
сабмодулей по SHA). Отдельно проверено: `ConfigCatalog.generated.swift`
совпадает с выводом `gen-config-catalog.py` байт в байт при путях как на
macOS и исходниках сабмодулей на закреплённых коммитах.

**Не проверено:** ни одного запуска на macOS-раннере; Swift- и C-части
проверок; сама сборка и IPA; установка на устройство.

## Что показали сборки на телефоне

- 575: «No, I'm not a Human» — «Failed to load il2cpp»: `GameAssembly.dll`
  не грузилась без 64-битной `wintypes.dll` (её даёт
  `api-ms-win-core-winrt-robuffer-l1-1-0`). 576 собирает `wintypes`
  вместе с другими дополнительными Wine-DLL (`tools/build-wine-extra-dlls.sh`).
- 576: игра запускается, но круглой кнопки меню нет, и без контроллера из игры
  не выйти. Вероятная причина: `Winios.m` вставлял компоновщик рабочего стола
  (у Dock-старта он с чёрным фоном) в ключевое окно. После касания экрана
  запуска ключевым становится окно сенсорного управления (+101), и
  компоновщик ложился поверх кнопки. 577 вставляет его в окно `MetalHostView`
  (окно самого приложения), а ключевое окно берёт, только если хоста ещё нет.
  Лог 577 покажет `level=… key=…` у строки `[winios] compositor attached`
  и строки `[controls] key window=…`. Если окно управления осталось на старой
  сцене, оно привязывается к текущей.
- 577: кнопка меню видна. Лог подтвердил причину: `compositor attached …
  level=0 key=0`, то есть окно игры в этот момент не было ключевым.
  S.T.A.L.K.E.R.: Shadow of Chernobyl (Dock-старт) падает после создания окна
  D3D: `ReadProcessMemory` своего процесса читает 128 байт перед образом exe,
  страница PROT_NONE. В Windows это ошибка `STATUS_PARTIAL_COPY`, у нас —
  SIGBUS в `memmove` внутри `NtReadVirtualMemory`. `bus_handler` не звал
  `handle_syscall_fault` (а `segv_handler` зовёт), поэтому `__TRY` не
  срабатывал: «Exception frame is not in stack limits», процесс убит. На
  экране остаётся заставка мёртвого процесса. 578: AV внутри системного вызова
  на пути SIGBUS возвращается в `__TRY` вызова или вызывающему как ошибка,
  в логе строка `[bus-syscall]`.

## Сборка 581 (22.10)

- Слияние с BCD 0.1.580 (`f5deb72`): что решено в конфликтах, сказано в
  сообщении коммита. Номер 581: 579 и 580 уже заняты релизами апстрима с тем
  же bundle ID.
- Blender (Steam 365670): `blender.exe` завершался с `c0000135`, потому что
  не находил свои DLL из `blender.shared\` (`tbb12.dll`, `OpenImageIO_Util.dll`
  и ещё 13). Его манифест сначала требует `Microsoft.Windows.Common-Controls`
  6.0, а `actctx.c` бросает весь контекст активации на первой ненайденной
  зависимости. В winsxs были только сборки `x86_`, а 64-битный процесс
  (ARM64EC) ищет `arm64_`. 581 записывает манифест
  `arm64_microsoft.windows.common-controls_…` без файлов: зависимость
  выполнена, а `comctl32.dll` по-прежнему грузится из system32.
- Чего ждать: Blender дойдёт до OpenGL. OpenGL и Vulkan на iOS в этом
  стеке нет (`Wine was built without Vulkan support`), так что ожидаемое
  следующее сообщение — «требуется OpenGL 4.3». Это следующий шаг.
- Запуск 39756022204 упал на «Check [x87-int64] and the fault neighbour
  lines»: тестовая программа из апстрима 0.1.578 выделяет память по
  жёстким адресам (`0x5000000000`, `0x300000000 + …`), а в процессе на
  раннере macos-15 они были заняты (`alloc-failed`). Так же устроена
  `check-wow-null-diag.py`, она идёт следом. В обеих проверках адреса теперь
  берутся из одной свободной области на 8 ГБ, выровненной на 4 ГБ.
  Ожидаемые значения не меняются: в них только гостевые числа.
