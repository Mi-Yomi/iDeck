# iDeck-BCD: крупные изменения 19 октября 2026

Реализация пунктов «Крупно» из `docs/audit/BCD-AUDIT-0.1.574-20261019.md` и
поддержки Unity-игр. Решения владельца на этот раз: сборочный конвейер
(пункт 12) позже; нативные и Swift-изменения только за флагами, выключенными
по умолчанию; разбивка больших файлов и перенос префикса откладываются до
первой сборки, по префиксу нужен только план.

**Ничего не собрано и не запущено.** На этой машине нет Xcode, Swift и
C-компилятора. Тесты проекта не запускались (`AGENTS.md`). Всё ниже —
исходный код и статическая самопроверка.

## 1. Адаптивная арена FEX (`arena-adaptive`, по умолчанию выкл.)

`build/ntdll-unix/virtual_ios.c`: `ios_arena_largest_hole`,
`ios_arena_adaptive_trim`, вызов перед `sc_arena_placed:` в
`ios_reserve_fex_arena`.

Проблема (лог владельца, сборка 573, iOS 27, без Extended VA): карта
заканчивается на `0x7180000000`, высокая полоса FEX 16 ГБ недоступна, лестница
доходит до «4GB @32-48G», ядро ставит арену в низ последнего большого
диапазона, гостю остаётся ~1.4 ГБ кусками. UnityPlayer резервирует блоки по
512 МБ, второй не помещается (крупнейшая дыра 369 МБ) → `c0000017` → запись по
NULL → цикл исключений.

Что делает флаг: после резервирования арены меряет крупнейшую свободную дыру
(обход `mach_vm_region_recurse`, как в `ios_ml1027_place`). Пока она меньше
`arena-guest-min-mb` (2048) и арена больше `arena-floor-mb` (2048, минимум
1024), отдаёт верхние 512 МБ арены. Освобождённый кусок примыкает к
свободному месту над ареной, база не двигается. Если дыра не выросла, хвост
мапится обратно. Полосу 16 ГБ (устройство с большой картой) не трогает. В логе
строки `[fex-arena] ideck-adaptive ...`.

Риск: меньшая арена вмещает меньше потоков FEX (по ml756 ~3.5 ГБ на ~74
потока). Поэтому это флаг на уровне игры, а не значение по умолчанию.

## 2. Unity-игры

- Новый вид совпадения в рекомендациях: `"filesBeside": ["unityplayer.dll"]`
  (`GameRecommendationsList.swift`: модель, разбор, проверка;
  `GameRecommendations.swift`: `hasAll`, папка Steam-установки и папка exe;
  собственные правила игр идут раньше).
- Правило `unity` в `recommended/recommendations.json` (перед `standard`,
  версия файла 2): стандартная строка + `arena-adaptive = 1`.
- Не добавлено без доказательств: `env.MADEIRA_X64_IMAGE_NOCOPY` для IL2CPP.
  В запуске с «Failed to load il2cpp» (сборка 574) auto-tune не нашёл
  совпадений, значит JIT-пул причиной не показан. Нужен лог этого запуска.
- Не добавлено правило auto-tune: по правилам репо каждое правило
  подтверждается фикстурой, а движок на Swift здесь не прогнать.
- Как получить: игра, у которой ещё нет своих строк, получает список при
  первом появлении; у игры со своими строками — «Reset to Recommended» внизу
  её настроек.
- Риск: встроенный список заменяется скачанным с апстрима, если там версия
  выше (`GameRecommendationsSource.swift`, `initialList`). Апстримная v3 уберёт
  правило `unity`. Лечится своим источником рекомендаций (пункт 7 аудита).
- Замечание из кода (`virtual_ios.c`, task#29): «extended-VA is not available
  to free personal teams». На бесплатном Apple ID Extended VA, по опыту
  авторов, не получить; `arena-adaptive` — обходной путь именно для такого
  устройства.

## 3. Тише логи (`log-quiet`, по умолчанию выкл.)

`virtual_ios.c`: `ios_log_quiet`. При `log-quiet = 1` не пишутся обычные
построчные `[valloc]`/`[vfree]` и заголовки `[bigres]` кроме первых 64 и
каждого 256-го. Остаются: адрес vmwatch, ограниченные и нарушающие лимит
выделения, всё, что читает auto-tune (`[valloc]`, `[vfree]`, `[bigres]` правила
не используют). Сэмплеры и профайлеры уже имеют свои ключи:
`env.MADEIRA_LEAN_DIAG = 1`, `env.MADEIRA_PROBES = light`.

## 4. Каталог настроек

Новые ключи в `OVERLAY` у `build/tools/gen-config-catalog.py` и строки в
`app/Madeira/ConfigCatalog.generated.swift`: `arena-adaptive`,
`arena-guest-min-mb`, `arena-floor-mb`, `log-quiet`. Строки отрисованы функцией
`render()` самого генератора и вставлены в позицию его сортировки. Полный
прогон генератора здесь невозможен: его `scan()` читает исходники сабмодулей
Wine/FEX, которых в этом клоне нет, и выбросил бы их записи. На Mac с
сабмодулями `gen-config-catalog.py --check` должен совпасть.

## 5. Префикс в Documents: план (не реализовано)

Факты из кода:

- Префикс — `Documents/wine` (`MadeiraDock.swift`, `prefix`); `Info.plist`
  включает `UIFileSharingEnabled` и `LSSupportsOpeningDocumentsInPlace`,
  значит весь `drive_c` виден в «Файлах» и через Finder по USB и попадает в
  резервные копии, если не исключён.
- Steam-клиент внутри Dock хранит состояние входа (`local.vdf`) и cookies в
  `drive_c/users/<user>/AppData/Local/Steam` (`SavesAndShortcuts.swift`), свой
  кеш сессии и кешированные лицензии для офлайна (README и `docs/OFFLINE.md`
  у madeira-dock); Dock их не читает и не пишет.
- Передача токена в Dock уже сделана правильно: Application Support, 0600,
  complete protection, исключено из бэкапа (`MadeiraDock.writeHandoff`).

Варианты по возрастанию риска:

| Шаг | Что | Риск |
| --- | --- | --- |
| A | `isExcludedFromBackup` на `AppData/Local/Steam` и `Program Files (x86)/Steam/config` при каждом старте сессии | минимальный: в «Файлах» видно по-прежнему |
| B | Перенести эти две папки в `Application Support/SteamState`, в префиксе оставить символические ссылки (Wine их проходит) | средний: нужна миграция и проверка, что офлайн-вход и Steam Cloud не ломаются |
| C | Весь префикс в Application Support, в Documents только папка импорта игр | высокий: установленные игры, сохранения, привычный путь через «Файлы» |

Рекомендация: A сразу после появления сборки, B после проверки на
устройстве (вход, офлайн, Steam Cloud, переустановка BCD), C не делать без
отдельного решения.
