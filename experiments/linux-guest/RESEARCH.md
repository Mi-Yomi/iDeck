## Consequence of the new Steam measurements

Valve manifest version `1791918634`, SHA-256 `65079d08bbcc0e7fdc3d9b153aadc4c9befc62913c3e4ee0b02425690366f15f`, was obtained from the exact CDN in the pinned DroidDeck installer. Six selected architecture-specific ZIPs passed manifest size/SHA-256 checks. Their 87 ELF files, including all three key client/CEF objects, report `ELF64`, little-endian, `EM_AARCH64`.

GNU readelf independently confirmed the three key objects and dynamic dependencies. Highest GLIBC version requirements observed in these objects: Steam 2.29, steamwebhelper 2.29, libcef 2.25. This is **not** the minimum for every dependency in a complete installation. The required `/lib/ld-linux-aarch64.so.1` was not shipped in the six inspected ZIPs. No loader from a future rootfs has been verified yet.

Thus no x86 CPU translator is indicated for these measured client/CEF objects inside an AArch64 Linux guest. Games, Proton and optional components must be classified separately. X11/GLib/NSS/DBus/DRM/GBM/audio dependencies are real and remain part of the glibc rootfs/CEF acceptance gate. The actual DT_NEEDED lists and hashes are in `evidence/steam-abi.json`.

## Decision and remaining proof

Continue the requested direct Linux guest experiment with Husk's reusable VM components. The new proof is host kernel + framebuffer + input; the next acceptance is that **same probe on the target iPhone through the real JIT and Metal bridge**. Then assemble an independent glibc ARM64 disk and verify loader resolution, Xorg and software Mesa before installing the complete official client and launching `-gamepadui`.

Big Picture acceptance remains: actual Linux Steam and CEF processes, readable client UI, user-performed sign-in, library → game detail → back using phone input, and at least three minutes of a live session with correlated logs. Software scanout is not game GPU acceleration. No FPS prediction follows from this host control.

REA was not needed: repository sources, exact package hashes, the ELF parser and GNU readelf resolved the relevant ABI question without decompiling or running Steam.
